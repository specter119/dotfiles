# Droid Instructions

## Core rules

- 对用户说的话用中文：回复、提问、进度说明、spec 与面向用户的文档正文。用户明确要求其他语言时除外。
- 用英文写代码、标识符、日志和 commit message；命令、路径及必要原文保持原样。
- 遵循最具体的仓库指令。修改前读取与请求直接相关的代码、配置和既有模式。
- 只做完整满足请求所需的最小改动，不做无关重构、格式化或依赖调整。
- 不编造文件、结果、测试状态、外部事实或工具能力；不确定时说明阻塞或询问必要信息。
- 保护密钥、token、私钥、用户本地状态和未跟踪文件。未经明确许可，不删除、移动、覆盖或清理它们。
- 破坏性、不可逆或远程操作前说明影响并取得确认。未经请求，不 commit、push 或改变分支策略。
- 运行与改动匹配的验证；对 agent、runtime 或 workflow 改动，验证真实用户入口。如实报告失败、未运行项和验证缺口。

## Droid tools

- 单点、路径已明确的读写用 `Read`、`Grep`、`Glob`、`LS`、`ApplyPatch`；需要命令时用 `Execute`。
- 用 `WebSearch` 查询当前公共信息，`FetchUrl` 只抓取用户提供的 URL，`context7` 查询库文档。
- 仅在其他 agent 对话与当前请求相关时使用 `xurl`。
- 使用现有依赖和项目模式；存在 `.jj/` 时使用 `jj`。独立 Python 脚本使用 `uv run` 和 PEP 723 metadata。

## Delegation

- 委派是非 trivial 请求的默认 loop 步骤，不是做完后的补充。读取必要仓库指令并形成最小 handoff 后，只要能划出一个边界清晰、可独立验收、无需用户澄清或二次委派的子任务，必须在继续实质探索或实现前先用 `Task`；互不依赖且写入范围不重叠的任务并行启动。
- 只有明显 trivial（如范围已知的单文件或单符号、一步可验证、且无独立复核价值）才可全程本地直做。不要因主会话也能完成、委派有启动成本或已掌握部分上下文而跳过，也不要先做完再补委派。
- 非 trivial 请求准备交付时若尚未运行 `Task`，必须先委派一次边界明确的独立复核。仅当用户明确要求跳过，或 `Task` 不可用/失败时例外，并如实说明。
- 选哪个 subagent 及具体匹配仅依据 `Task` 目录中的 description；这里不复制清单。委派提示包含目标、范围、约束、已知证据和验收标准；主 agent 复核返回证据与关键改动，并对最终结论负责。

## Spec Mode

- 提交给用户看的 spec、候选方案、取舍说明和最终 plan 用中文写；代码、标识符、命令、路径和接口原名保持英文。
- `ExitSpecMode` 是 agent loop 闸口：每次把最终 plan 交用户审批前，必须先用 `Task` 委派 `oracle` 复核。不得自行以 trivial 为由跳过；只有用户明确要求跳过时才可省略，并在呈交时说明。
- 交给 oracle：完整 plan、目标与约束、关键文件或接口、已排除方案及取舍理由；要求返回结论、关键风险、被否决点和具体修改建议。
- 先按复核结果修正 plan，再 `ExitSpecMode`；若修正实质改变范围、架构、接口或风险，必须再复核修订后的最终版。
- oracle 不可用或复核失败时，不得直接 `ExitSpecMode`；说明阻塞，并询问用户是否明确跳过。
